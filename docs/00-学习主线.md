## 0. 怎么用（三步）

1. **看你在哪个里程碑** → 打开 `docs/progress/state.md`
2. **查这个里程碑该读哪几节** → 本文 §3「按里程碑的阅读主线」
3. **读完打勾** → 本文 §4「精读清单」，同时在 `docs/progress/reference-tracking.md` 记状态

**不要通读教程。** 35 节里只有 12 段值得精读，合计约 6 天；其余要么已会，要么与项目无关，要么卡住时查一下。

四种读法，写在判定列里：

| 判定 | 含义 | 怎么读 |
|---|---|---|
| **精读** | 项目直接依赖，不读就写不出来 | 从头读到尾，边读边在项目里落代码 |
| **摘读** | 只需要其中一两节 | 按本文给的小节号跳读 |
| **查阅** | 有基础，卡住时查 | 不主动读，遇到具体问题再翻 |
| **跳过** | 已会 / 与项目无关 / 明确砍掉 | 不读。理由写在 §5，防止以后反复动摇 |

## 5. 跳过清单与理由（防止反复动摇）

| 跳过 | 理由 |
|---|---|
| 微调 6 章（28–33） | 问题是缺数据和缺流程，不是模型不懂领域语言 |
| Coze 全系（5、6） | 不用 |
| 平台知识库（2） | 平台操作 ≠ 工程能力 |
| 企业级部署 / Xinference（7） | 另一条战线，3–6 个月且不共享技能 |
| 自建 MCP Server（20 §4.2、§6） | 数据源是内部函数，包成 MCP 只多一层故障点 |
| 多智能体实操（26 实操部分） | 只有一个真 Agent，加多智能体会让系统难测、归因变难 |
| 深度研搜项目 | 架构相反，学了会动摇现有边界 |
| 面试题库 | 不属于项目范围 |
| Skills 机制（27） | 那是我的工具，不是项目能力 |

**规则**：这张表里的东西，只有一种情况可以重新考虑——项目需求变了。不是「看到了觉得有用」。

## 6. 三处教程与我的做法相反（别被带回去）

| 教程怎么说 | 我怎么做 | 为什么 |
|---|---|---|
| 把 MCP 通过 `McpClientAgent` 交给 Agent 自己选工具（20 §4.3、21 §5.4） | 写死工具名，直接 `tools/call`，原始 JSON 过 Pydantic | 数据获取是确定性工作流，让模型选工具会引入不确定性并浪费额度 |
| 多智能体 + 子智能体做深度研搜 | 单 Agent + 三个确定性工作流 | 多智能体难测、成本不可预测、错误归因变难 |
| 先搭平台（Dify/Coze）再写代码 | 先写代码，Dify 只留 2 个工作流做对照 | 平台会掩盖工程细节，我要能讲清每一层 |
